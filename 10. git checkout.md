## 14. Resolving Merge Conflicts

**Merge conflict** occurs when Git cannot automatically combine changes.

Basic process:

```
Merge
 ↓
Conflict
 ↓
Manually fix file
 ↓
git add .
 ↓
git commit
```

Conflict markers:

```
<<<<<<< HEAD
Your changes
=======
Other changes
>>>>>>> branch
```

Remove the markers after resolving.

## 15. `git reset`

Used to move HEAD to another commit.

### Soft

```
git reset --soft HEAD~1
```

- Removes commit.
- Keeps changes staged.

### Mixed

```
git reset HEAD~1
```

- Removes commit.
- Keeps changes unstaged.

### Hard

```
git reset --hard HEAD~1
```

- Removes commit and changes.

⚠️ `--hard` can permanently discard work.

---

## 16. `git revert`

Used to undo a previous commit **by creating a new commit**.

```
git revert <commit-hash>
```

### Reset vs Revert

|Reset|Revert|
|---|---|
|Rewrites history|Preserves history|
|Moves HEAD|Creates new commit|
|Can be destructive|Safer for shared branches|

---

## 17. `git stash`

Temporarily saves uncommitted changes.

```
git stash
```

View stashes:

```
git stash list
```

Restore:

```
git stash pop
```

Apply without removing:

```
git stash apply
```

### Use case:

```
Working on Feature A
        ↓
Need to switch branches
        ↓
git stash
        ↓
Do other work
        ↓
Return to Feature A
        ↓
git stash pop
```
